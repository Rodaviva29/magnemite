Two ways to run the stack: [docker compose behind your own
proxy](/docs/deployment/docker-compose), or [Coolify](/docs/deployment/coolify).

<Steps>

<Step>

### Bring the stack up

```sh
git clone https://github.com/Rodaviva29/magnemite.git && cd magnemite
cp .env.example .env
$EDITOR .env      # DATABASE_URL, MAGNEMITE_PUBLIC_URL, two secrets
make up
```

The stack runs no database of its own — `DATABASE_URL` points at one you
already have. It publishes plain HTTP on `EDGE_PORT` (8080) and never binds 80
or 443: point a virtual host on your reverse proxy at `http://127.0.0.1:8080`
and terminate TLS there.

</Step>

<Step>

### Sign in

Open your domain, log in with `ADMIN_EMAIL` / `ADMIN_PASSWORD`. The admin
account is created on hub boot; sign-up is disabled by design.

`make seed` is optional and adds a starter app target, two version sources, a
group and a first **enrollment token** — printed once. Skip it and set the same
things up from **Settings**.

</Step>

<Step>

### Build the Magisk module

`SERVER` is the **hub** URL — the same value as `MAGNEMITE_PUBLIC_URL`, never
the dashboard's.

```sh
make module SERVER=https://magnemite.example.com TOKEN=<enrollment token>
# → dist/magnemite-agent-1.0.0.zip
```

Windows: `./scripts/build-agent.ps1 -Server https://… -Token <token>`.

</Step>

<Step>

### Flash a box

```sh
adb push dist/magnemite-agent-1.0.0.zip /data/local/tmp/
adb shell "su -c 'magisk --install-module /data/local/tmp/magnemite-agent-1.0.0.zip'"
adb reboot
```

In bulk over the LAN: `./scripts/enroll.sh dist/magnemite-agent-1.0.0.zip -f hosts.txt`.

</Step>

<Step>

### Watch it appear

The box enrolls itself on first boot and shows up in the fleet table with its
serial, model, installed versions and free space.

That is the only hands-on step. Every later update — the agent's own included —
rides the socket the box opened.

</Step>

</Steps>
