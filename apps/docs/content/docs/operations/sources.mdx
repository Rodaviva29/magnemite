A **source** is a URL publishing an index of installable builds. Magnemite has
no special-cased integrations: every source is a row you can add or remove in
**Settings → Version sources**, and they all speak the same format.

| Source                         | Index                                                       | Notes                                                        |
| ------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------ |
| `UnownHash mirror`             | `https://mirror.unownhash.com/index.json`                   | Bare filenames, so it needs a base URL. Publishes an md5.    |
| `Silva (The Treeline Project)` | `https://the-treeline-project.github.io/p/silva/index.json` | Absolute `url` per entry, plus `package` and `version_code`. |

Both ship `com.nianticlabs.pokemongo` as an arm64-v8a `.apkm`, a zip holding
`base.apk` plus `split_config.arm64_v8a.apk`. That is why installs go through a
`pm install-create` / `install-write` / `install-commit` session rather than a
plain `pm install`.

## The index format

A flat JSON array. Four fields are required; the rest are read when a source
publishes them and ignored when it does not.

```json
[
  {
    "filename": "com.nianticlabs.pokemongo_arm64-v8a_0.425.0.apkm",
    "version": "0.425.0",
    "arch": "arm64-v8a",
    "size": 250184385,
    "package": "com.nianticlabs.pokemongo",
    "version_code": "2026081202",
    "md5_hash": "",
    "last_modified": "2026-08-15T13:55:23.000Z",
    "url": "https://…/com.nianticlabs.pokemongo_arm64-v8a_0.425.0.apkm"
  }
]
```

| Field                                 | Used for                                                                            |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| `filename`, `version`, `arch`, `size` | Required. Matching the target and knowing what is being downloaded.                 |
| `url`                                 | The download. Without it, the source needs a **base URL** to prefix `filename`.     |
| `package`                             | Matching the target exactly. Without it, the filename prefix is used instead.       |
| `version_code`                        | The Play build code shown next to the version.                                      |
| `md5_hash`                            | Checked at download time. Empty or absent means the size is the only upfront check. |
| `last_modified`                       | The published date in the Versions table.                                           |

## Adding one

**Settings → Version sources → Add source**: a name, the index URL, and a base
URL only if the index lists bare filenames. It is polled on the next cycle, and
**Settings → Health** gets a card for it showing how many builds it lists and
when it was last read.

Removing a source stops the polling. Builds it already found stay, cached
artifacts and rollout history included — they simply no longer name a source.

## Two sources, one build

When several sources list the same build it is stored **once**. The source with
the lowest **priority** number decides which URL is downloaded; the others only
fill in metadata it did not publish, such as an md5 or a build code.

That is why adding a source never duplicates the Versions page, and why a new
source is added last by default: an existing build keeps being downloaded from
where it already was.

## What the hub does with them

1. Polls every enabled source every poll interval (**Settings → Hub
   settings**, 15 minutes by default) and records what it finds as
   **versions**.
2. Downloads a version **once**, when it is cached (either by you pressing
   _Cache_ or by auto-update).
3. Computes a **sha256** while writing it to `ARTIFACT_DIR`.

That sha256 is what each agent verifies before it opens an install session. The
upstream md5, where a source publishes one, is checked at download time; without
it the size the index reports is the only upfront check.

<Callout type="info">
  Sources are polled independently, so a build that appears on one first is available immediately
  rather than waiting for the others to catch up.
</Callout>

## Pruning

Cached bundles are ~170 MB each and accumulate. **Versions → Prune** removes
artifacts for versions nothing is on and nothing is rolling out to, leaving the
database rows.

## Configuration

Sources live in the database, not in `.env`, and are entirely managed from
**Settings → Version sources** — add, edit, or remove as many as you like
there, no env var involved. The poll interval itself is in **Settings → Hub
settings**, alongside the other operational knobs — see [environment
reference](/docs/deployment/environment).

The optional `pnpm db:seed` / `make seed` adds two starter sources (the
UnownHash mirror and Silva) on a fresh database, as a convenience — skip it
and add your own from Settings instead if you'd rather start empty.

Leave **Base URL** empty for an index that publishes an absolute `url` per
entry. If it lists bare filenames instead, set the base URL in Settings; the
Health card says so when entries have nowhere to download from.
