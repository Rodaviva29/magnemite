The device page's **Load** card is what a box is doing right now, with the last
hour behind each number as a sparkline. The chart icon opens **Load history**:
the same readings over a window you choose.

## What the box reports

Every heartbeat — one every 20 seconds — the agent reads a few small `/proc`
files and sends them with the package versions:

| Reading         | Where it comes from                              |
| --------------- | ------------------------------------------------ |
| CPU load        | `/proc/loadavg`, against the box's core count    |
| Memory          | `MemTotal` and `MemAvailable` in `/proc/meminfo` |
| Storage         | `/data` — the partition an install writes to     |
| Temperature     | `/sys/class/thermal/thermal_zone*`               |
| CPU/RAM per app | `/proc/<pid>/stat` and `statm`, per tracked app  |

**Temperature** is the awkward one: plenty of TV boxes expose no thermal zone,
and those that do disagree about units. The agent picks the divisor by
magnitude and drops anything outside −30…150 °C, so a box that cannot say shows
nothing rather than something wrong. Unlabelled zones: the hottest wins.

**Per-app usage** covers only the tracked packages, summed across every process
an app owns. CPU is a share of a _single_ core — the number `top` shows — so
200% is two cores pinned.

<Callout type="info">
  A reading the box never sent is stored as null and drawn as a gap, never a zero. That is the
  difference between "the scanner was idle at 3am" and "the scanner was dead at 3am", which is the
  question the history exists to answer.
</Callout>

## Load history

One filter row scopes every chart below it: **time range** (presets longer than
the retention are disabled), **apps** (colours are fixed per package, eight at a
time), and a **table** of the same numbers as text.

Each chart carries `avg`, `p95` and `max` for its window. The p95 is there
because a mean hides the spike, and the spike is what is being looked for.
Charts are bucketed to about one point per pixel-column before they leave the
server; the statistics are computed from the raw rows, because an average of
averages is not the average.

## Retention

Two knobs in **Settings → Tuning**:

| Setting                          | Default | What it does                                                         |
| -------------------------------- | ------- | -------------------------------------------------------------------- |
| Health sample interval (seconds) | 60      | How often a heartbeat is kept. Below 20 stores every beat.           |
| Health history retention (days)  | 7       | How long samples live. 0 turns recording off and drops what is kept. |

At the defaults a box costs about 1 400 rows a day, plus one per tracked app.
The hub prunes hourly in batches, so the delete never locks the table against
the heartbeats writing to it.

<Callout type="warn" title="Nothing recorded in this window yet">
  Expected on a box that just enrolled, on an agent old enough not to send these fields, and with
  retention set to 0.
</Callout>

## Extra version columns

The fleet table shows the installed version of each app Magnemite updates. Any
other package can have a column too — the scanner being the obvious one.
**Settings → Fleet columns → Add column**: a package name, optionally a shorter
header.

```
com.pokemod.aegis    →  header "aegis"
```

It sorts, searches and groups like every other column. Magnemite **does not
update these** — it only asks each box what it has, which is the whole
difference from an app target: no rollouts, no versions page, no auto-update.

The hub keeps one list of packages worth reporting — the app targets plus these
— and hands it to each agent in its `welcome`. Adding a column pushes the list
to every connected box, so it fills in on the next heartbeat; an offline box
picks it up when it returns. An empty cell means the box has not reported that
package: either it is not installed, or it has not been heard from since. The
settings tab shows how many boxes answered for each, which tells the two apart.

Removing a column stops the reporting. Recorded versions stay, and the device
page keeps listing every package a box reported — the column is a view, not the
record.
