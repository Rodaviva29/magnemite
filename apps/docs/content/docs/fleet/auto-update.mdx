**Settings → Auto-update.** When it is on, the hub:

1. polls each source on its own interval (**Settings → Version sources**),
2. caches the newest **approved** version onto the server,
3. creates a rollout with your canary and soak settings,
4. dispatches only inside the time window, if you set one.

## What it will not do

- **Never downgrades.** A source publishing an older build is ignored.
- **Never runs two rollouts for the same app at once.**
- **Does nothing at all** if every device is already on the newest version.
- **Only touches approved versions** (see below).
- **Waits out the cooldown**, if one is set (see below) — a fresh discovery
  right after the last auto-update finished does not immediately ship.

## Approval

Leaving **approve new versions automatically** off means a human ticks _approve_
on the Versions page before anything moves. That is a reasonable default while
you are still learning to trust it.

With it on, the pipeline is fully hands-off: a release appears upstream and the
fleet is on it.

<Callout type="warn">
  Auto-approve plus no canary means an upstream mistake reaches 200 boxes unattended. Keep a canary
  of at least a few devices, and a soak long enough that a scanner failure would show up — in
  [Rotom](/docs/fleet/rotom), or as a [monitoring](/docs/fleet/monitoring) alert — before the rest
  go.
</Callout>

## The time window

A window is the difference between 35 GB of egress at 04:00 and 35 GB during
your peak scanning hours. Jobs created outside it stay queued; the scheduler
dispatches them when it opens.

## Polling

**Check every**, on each source in **Settings → Version sources**, defaults to
15 minutes. It is per source rather than fleet-wide, because an index is
somebody else's server: a mirror that publishes hourly and one that publishes
on release do not want the same cadence. Sources come round independently, so
a build that appears on one is picked up without waiting for the others. A poll
of everything can be forced from the Versions page, and a changed interval
takes effect within seconds, no restart needed.

## Cooldown

**Cooldown**, on the app itself in **Settings → Apps**. We don't always need
to update the moment a new build appears — a fresh Pokémon GO release is
sometimes worth watching for a day or two before it touches your fleet. Set
this to however many minutes (hours, days — just do the math) should pass
since an app's **last** auto-update rollout finished before another one is
allowed to start. Discovery and polling keep happening regardless; only the
"ship it automatically" step waits. Defaults to 0 — no cooldown, update the
moment a new approved version is found, the historical behavior. Per app,
because a scanner people watch all day and a launcher nobody notices do not
want the same restraint.
